# One-shot automatic USDT-M paper cycle

Run one credential-free BTC/ETH USDT-M paper cycle for a required real `date` (`YYYY-MM-DD`) and `isoWeek` (`YYYY-Www`). This skill may create simulated fills, but never submits an exchange order.

1. Run `scripts/crypto-automation.mjs doctor` for the selected configuration. If it returns `SETUP_REQUIRED`, stop and show the `npm run paper -- init` command with placeholders for every user-supplied capital, loss, drawdown, spread, entry-distance, and slippage value. Never infer these values.
2. Run `scripts/crypto-automation.mjs prepare` for the requested anchors with `--exchanges all --channels core`. It must settle existing paper positions first, then collect and seal the CCXT registry, write `data/crypto_multi_exchange.json`, collect the Gate snapshot, and embed the sealed cross-venue aggregate. A multi-exchange `PARTIAL` result is valid; `BLOCKED` is not. Stop on any credential, configuration, settlement-evidence, or Gate-data failure.
3. If `anchor_action` is `REFRESH_WEEKLY`, launch `.claude/workflows/crypto-analysis.mjs` with `tier: "weekly"`, persist its exact `document` through `scripts/agent-write.mjs` as `data/crypto_strategy.json`, and render the weekly report. Do not continue unless the canonical anchor is active for the requested ISO week.
4. Launch the same workflow with `tier: "daily"` and the same anchors/configuration. Its subagents remain read-only. Persist the exact `document` as `data/crypto_daily.json`, then render `outputs/daily-<date>.md`.
5. Run `scripts/crypto-automation.mjs plan` with the same anchors and configuration. It performs deterministic USDT-M selection, writes a sealed plan, applies only the paper fill model, updates the paper ledger, and writes the cycle/performance reports. Report the outcome and artifact paths exactly; `BLOCKED` is a valid fail-closed result.

The process must not contain any Gate or Binance USDT-M testnet credential. Do not invoke Spot planning, run either testnet executor, add a timer, submit an order, turn on testnet mode, or infer capital. Venue lifecycle fields must remain `submitted: 0` and `filled: 0`; simulated contracts are reported only as `simulated_filled_contracts`.
